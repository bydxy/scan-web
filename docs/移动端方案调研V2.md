# 移动端实时扫码网站 · 技术方案调研报告（V2）

> 调研时间：2026-08-25 ｜ 场景：手机浏览器实时预览扫码，识别二维码/条形码等多码型，Apple 风格 UI

---

## 一、关键结论（先看这个）

1. **iPhone 上原生 BarcodeDetector API 依然不可用**（截至 2026 年 Safari 17~27 全线禁用，且 iOS 18 一度有 bug），所以**必须准备 WASM 降级引擎** —— 这决定了整体架构
2. **Android Chrome 系**（含微信内置浏览器）走原生 API，硬件加速，零体积
3. 最强降级引擎是 **`@sec-ant/zxing-wasm` / `barcode-detector` ponyfill**（⭐260，昨天还在更新），它把 ZXing-C++ 编译成 WASM，并封装成与原生 API **完全相同的接口**
4. 苹果风格 UI 的正确姿势是 **Liquid Glass**（iOS 26 新设计语言，WWDC 2025 发布），iOS 26 Safari 甚至能通过 `-apple-visual-effect` 直接调用系统原生玻璃材质

## 二、扫码引擎选型（移动端视角）

### 2.1 引擎对比

| 引擎 | 技术 | 码型覆盖 | 手机端表现 | 维护 |
|---|---|---|---|---|
| 原生 `BarcodeDetector` | 浏览器内置(Google Lens ML) | QR/EAN/UPC/Code128/PDF417/Aztec/DataMatrix | Android 硬件加速最快 | Chrome 平台 |
| [`@sec-ant/barcode-detector`](https://github.com/Sec-ant/barcode-detector) (ponyfill) | ZXing-C++ → WASM | 同上，全格式 | 各平台一致，~100KB gzip | 🟢 极活跃(2026-08) |
| [`Sec-ant/zxing-wasm`](https://github.com/Sec-ant/zxing-wasm) | 同上底层库 | 全格式 | 直接用 WASM 模块 | 🟢 极活跃 |
| `nimiq/qr-scanner` | jsQR + Worker | 仅 QR（少量条码） | 轻量快，但码型少 | 🟡 一般维护 |
| `html5-qrcode` | 纯 JS | 主流 | 慢一些，自带 UI 重 | 🟢 活跃 |
| `jsQR` | 纯 JS | 仅 QR | 图片识别强，无相机逻辑 | 🟢 活跃 |

### 2.2 推荐策略：统一接口的双引擎

```js
// 伪代码：一个接口，两个后端
if ('BarcodeDetector' in window) {
  engine = new NativeDetector(formats);        // Android：零成本最优
} else {
  engine = await import('barcode-detector/pure'); // iOS/其他：WASM 全格式兜底
}
```

> 业内实践参考：开源项目 `marianmeres/scanner` 甚至**故意完全忽略原生 API**、无条件使用 zxing-cpp WASM ponyfill，理由是原生 API「各平台行为不一致、历史 bug 多」。我们的建议是保留原生优先（性能更好），但把 ponyfill 作为标准降级路径。

### 2.3 为什么不用 html5-qrcode / jsQR 做主力？

- 本项目需要**条形码等多码型**：jsQR 只支持 QR ❌
- html5-qrcode 纯 JS 解码速度明显慢于 WASM，实时预览帧率吃亏，且自带 UI 与 Apple 风格定制冲突 ❌

## 三、移动端相机与 iOS 兼容要点（踩坑清单）

来自多个生产级项目的实战经验：

| # | 要点 | 说明 |
|---|---|---|
| 1 | **HTTPS 强制** | `getUserMedia` 只在安全上下文存在，部署用 GitHub Pages 天然满足 |
| 2 | **用户手势触发开摄像头** | iOS Safari 不允许页面加载自动开相机，必须有醒目的「开始扫描」按钮 |
| 3 | **`facingMode: "environment"`** | 调后置摄像头；提供前后切换按钮 |
| 4 | **权限被拒的状态处理** | 区分 PERMISSION_DENIED / NO_DEVICE / DEVICE_BUSY / INSECURE_CONTEXT，给出引导页（教用户去设置里恢复权限） |
| 5 | **后台被杀恢复** | iOS Safari 切后台回来可能杀掉视频流，用 `visibilitychange` + `sessionStorage` 自动重开会话 |
| 6 | **不要 auto-play 裸 video** | 需要 `playsinline` 属性防 iOS 全屏接管，`muted` 防自动播放拦截 |
| 7 | **对焦约束** | 手机网页拿不到连续自动对焦控制权，取景框要大、提示用户保持距离 |

## 四、Apple 风格 UI：Liquid Glass 设计体系

### 4.1 什么是 Liquid Glass

WWDC 2025 / iOS 26 发布的新材质语言，与旧 glassmorphism 的区别：

- **折射而非仅模糊**：背景像素被位移弯曲（透镜感），不只是磨砂
- **边缘光带**：边缘细亮边模拟凸面折光（specular highlight）
- **动态响应**：滚动/交互时玻璃微动

### 4.2 Web 实现三层方案

```css
/* 第 0 层：iOS 26 Safari 直接调用系统原生材质（真·系统玻璃） */
.apple-glass {
  border-radius: 20px;
  -apple-visual-effect: -apple-system-glass-material;
}

/* 第 1 层：通用基础（所有现代浏览器） */
.glass {
  background: rgba(255,255,255,.08);
  backdrop-filter: blur(16px) saturate(180%);
  -webkit-backdrop-filter: blur(16px) saturate(180%); /* Safari 必须带前缀 */
  border: 1px solid rgba(255,255,255,.12);
  box-shadow: 0 8px 32px rgba(0,0,0,.2);
}

/* 第 2 层：SVG feDisplacementMap 真折射（仅 Chromium，渐进增强） */
/* backdrop-filter: url(#refract) blur(12px) saturate(160%) */
```

`@supports not (-apple-visual-effect: ...)` 包一层即可优雅降级，两条规则吃满所有平台。

### 4.3 可用的开源组件库

| 库 | 特点 | 适用 |
|---|---|---|
| [JUNGHERZ/GlassKit](https://github.com/JUNGHERZ/GlassKit) | 24 个纯 CSS 组件，6.5KB gzip，零依赖，Dark/Light 双主题，mobile-first + safe-area-inset，Tab Bar/Dock 都有 | ✅ 最契合本项目 |
| dpawlikowski/liquid-glass | 纯 CSS+SVG 折射效果，React 可选 | 单点特效 |
| ObaidQatan/liquid-glass-component-library | React 19 + Tailwind 4 全家桶组件 | 若用 React 栈 |

### 4.4 扫码界面的苹果化设计要点

- 取景框：圆角矩形扫描窗 + 四角呼吸灯动画（类似系统相机）
- 结果卡片：底部 Sheet 弹出（iOS action sheet 手感），玻璃材质背景
- 工具按钮：胶囊形玻璃 pill button（46×46 触控热区 ≥44px）
- 字体：`-apple-system, SF Pro Text` 字体栈
- 深色模式：跟随系统 `prefers-color-scheme`
- 安全区：`env(safe-area-inset-bottom)` 适配全面屏

### 4.5 性能红线（中端安卓实测结论）

- 并发玻璃层 ≤ 3 个；blur 半径 8~16px 为宜（配 saturate 补偿）
- SVG 折射滤镜在 Adreno 660 以下 GPU 会掉帧 → 用 `navigator.deviceMemory` 检测降级为纯模糊
- 尊重 `prefers-reduced-motion`
- 相机预览是持续变化的背景，玻璃控件叠在上面时避免大面积 backdrop-filter

## 五、最终技术栈建议

```
┌─ 构建 ─────────── Vite 7（vanilla TypeScript，无需 React 这类重框架）
├─ 扫码引擎 ─────── 原生 BarcodeDetector 优先 → @sec-ant/barcode-detector(WASM) 降级
├─ 相机管理 ─────── 原生 getUserMedia 封装（手势触发/前后切换/权限状态机）
├─ UI ───────────── 纯 CSS 自定义 Liquid Glass（参考 GlassKit 设计令牌）
│                   -apple-visual-effect 渐进增强
├─ PWA ──────────── manifest.json + Service Worker（可添加到主屏幕、全屏沉浸、离线壳）
├─ 部署 ─────────── GitHub Pages（自动 HTTPS）
└─ 目标体积 ─────── 首屏 < 200KB gzip（WASM 引擎按需懒加载 ~100KB）
```

**页面结构（单页三态）：**

1. **首屏**：大标题 + 「开始扫描」主按钮 + 模式选择（相机 / 相册图片）
2. **扫描态**：全屏相机预览 + 玻璃取景框 + 顶部状态栏 + 底部工具 Dock（切闪光灯/切镜头/相册）
3. **结果态**：识别成功震动反馈 → 底部玻璃 Sheet 展示内容（链接直接跳转/复制/再次扫描），记录本地最近 20 条历史

## 六、风险与备选

| 风险 | 应对 |
|---|---|
| 微信等 App 内置浏览器的相机兼容 | 已验证 Chromium 内核支持原生 API；提供「在浏览器打开」引导兜底 |
| 条形码远距对焦困难（网页无对焦控制权） | 取景框做大 + 支持点击画面区域放大（CSS transform 数码变焦） |
| 低端安卓 GPU 玻璃特效掉帧 | deviceMemory < 4 时切换纯色半透明主题 |
| iOS PWA 内嵌 WebView 相机限制 | 引导用户用 Safari 打开而非主屏图标冷启动 |
