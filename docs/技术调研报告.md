## 二、四大主流技术方案

### 方案 1：原生 BarcodeDetector API（零依赖）

浏览器内置的条码检测 API，底层由 Google Lens 同款 ML 引擎驱动。

```js
const detector = new BarcodeDetector({ formats: ['qr_code', 'ean_13', 'code_128'] });
const barcodes = await detector.detect(videoEl);
// [{ boundingBox, cornerPoints, format, rawValue }]
```

- ✅ **优点**：零依赖、零体积、性能最强（实测比 ZXing WASM 快 2~3 倍）
- ❌ **缺点**：仅 Chrome / Edge 支持（2026 年已覆盖 94% 的 Chrome 安装）；Safari、Firefox 至今未实现；需要 HTTPS 安全上下文
- 📊 实测识别率（500 个真实商品码）：荧光灯 98.4% > ZXing WASM 96.2% > QuaggaJS 89.1%

### 方案 2：nimiq/qr-scanner（轻量性能派）

- 体积约 59 KB（gzip 后 16 KB）；若环境有原生 API 仅加载 15 KB
- 在 **WebWorker** 中运行，不阻塞主线程/UI
- 内置摄像头支持，**自动优先使用原生 BarcodeDetector**，无则降级为自带引擎
- 基准测试检出率为老牌 jsqrcode 的 2~8 倍，且无误读记录

### 方案 3：mebjas/html5-qrcode（功能全家桶）

- 自带完整扫描 UI（取景框、相机切换、文件上传），开箱即用
- 摄像头 + 图片双模式，文档完善，新手友好
- 缺点：体积较大（约 280 KB），定制 UI 需要覆盖较多默认样式

### 方案 4：cozmo/jsQR（图片识别专家）

- 纯 JavaScript、无任何依赖，约 45 KB
- **不包含**摄像头逻辑，只接收 `ImageData` —— 摄像头需自行接 getUserMedia
- 最适合「上传图片/截图识别」场景，也可在 Node.js 后端复用

## 四、推荐架构：渐进式增强（Progressive Enhancement）

```
页面加载
  │
  ├─ 'BarcodeDetector' in window ?
  │     ├─ 是 → 使用原生 API（Chrome/Edge 用户，零成本最优体验）
  │     └─ 否 → 加载 nimiq/qr-scanner（Safari/Firefox 用户降级）
  │
  ├─ 图片上传路径 → jsQR（或统一走上面同一引擎处理 ImageData）
  │
  └─ HTTPS 必须（getUserMedia 与 BarcodeDetector 的安全要求）
```

**推荐理由**：

1. 大多数国内移动端用户走微信内置浏览器 / Chrome 内核，能直接享受原生 API 的零体积与高性能
2. iOS Safari 用户自动降级到轻量 WASM/JS 方案，体验无断层
3. 单一解码入口封装成适配器层，后续替换引擎不影响业务代码

## 五、结论

- **快速上线/演示**：直接用 `html5-qrcode`，一天内出 Demo
- **正式产品**：`原生 BarcodeDetector + nimiq/qr-scanner 降级` 的组合拳，兼顾性能与兼容
- **纯图片识别工具站**：`jsQR` 单库即可满足，最省资源
- 避坑：instascan（停更 4 年）、quaggaJS（停更）不建议用于新项目；所有摄像头方案必须部署在 HTTPS 下
